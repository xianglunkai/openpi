1. 系统总图

推理把训练时的数据契约原路走回去。客户端只负责 ROS 与节拍，服务器负责模型。两边用 msgpack 打过 WebSocket。本页是开环 chunk：一块动作执行完再要下一块。相邻块的平滑属于 RTC 文档。

2. 两台进程各自拥有什么

训练产出的 50 步和客户端执行的 32 步不是矛盾。模型始终吐出 \(H=50\)。Broker 只消费前 32 拍就丢弃余下 18 拍并重新推理。这是用更新的观测换掉块尾部，降低开环漂移。RTC 文档会把这 18 拍改成重叠约束，而不是丢掉。

3. 可落地步骤

  1. 准备与训练一致的 checkpoint

    使用 pi05_cobot_screw_sorting_single 在 screw_sorting_single_sft_ep280_v30_steam 上训出的目录。服务脚本里的路径是：

    policy:checkpoint \
  --policy.config=pi05_cobot_screw_sorting_single \
  --policy.dir=/home/xlk/work/openpi/checkpoints/pi05_cobot/pi05_cobot_screw_sorting_single/pi05_cobot_screw_sorting_single/29999

    该目录必须含 params 以及 assets/<asset_id>/norm_stats.json。create_trained_policy 从 checkpoint 读统计量，保证和训练仿射变换相同。

  2. 先起策略服务器，prompt 用训练那一句

    export HF_ENDPOINT=https://hf-mirror.com
uv run scripts/serve_policy.py \
  --env COBOT \
  --default_prompt='Please sort and return the silver screws in the grey box to their proper places.' \
  policy:checkpoint \
  --policy.config=pi05_cobot_screw_sorting_single \
  --policy.dir=<上面的 29999 目录>

    --env COBOT 只影响元数据和是否走 Triton。JAX 权重走 model.load(restore_params(..., bfloat16))，然后 module_jit(sample_actions)。第一次请求会编译，耗时远长于后续的十几到几十毫秒，不要在编译完成前让机械臂离开复位。

  3. 机器人侧拉起 ROS，再跑客户端

    相机和关节话题由 Cobot Magic 的 launch 提供。real_env.RosOperator 同步取一帧高位图、左腕、右腕和双臂 JointState。单臂开关在 main.py 默认 use_single_arm=True，SINGLE_ARM_NAME="right"。

    source examples/mobile_aloha_AgileX/.venv/bin/activate
python -m examples.mobile_aloha_AgileX.main --host <策略机 IP> --port 8000

    客户端打印的 server metadata 出现后，Runtime 会先 environment.reset()：双臂平滑走到 _reset_position_left0 / right0，夹爪约 0.09。人确认工作台灰盒与银色螺丝在高位相机视野内，再开始 episode。

  4. 核对第一帧观测形状

    在 Policy.infer 入口，单臂观测应当是：

    {
  "state": float32 (7,),          # 右臂 6 关节 + 夹爪
  "images": {
    "cam_high": uint8 (3, 224, 224),
    "cam_right_wrist": uint8 (3, 224, 224),
  }
}

    没有 prompt 键是正常的。服务端 InjectDefaultPrompt 补上训练句子。若客户端误把 14 维双臂 state 传上来，delta 掩码只作用于前 7 维，右臂会被当成左臂，动作会完全错位。

  5. 看一块动作是否像示教

    返回的 actions 已是绝对关节，形状 (50, 7)。前 6 维应落在复位姿态附近的小增量上，而不是 \([-1,1]\) 的归一化数。夹爪在接近螺丝前维持张开，抓取时下降。若整段贴着 0，多半是反归一化没读到 q01/q99。若关节猛跳，先查是不是把 delta 又加了一次 state。

  6. 按 32 拍开环执行，必要时再打开插值

    ActionChunkBroker 在本地缓存整块，每控制拍吐出一行。real_env.step 在单右臂模式下把这 7 个数发给右臂，左臂目标保持复位。默认 main.py 关闭插值。若关节指令太疏，改用 main_rtc.py 那套 use_action_interpolation=True, multiplier=3，控制频率变成 \(30\times 3=90\) Hz，相邻两拍之间线性补点。那已经跨进 RTC 客户端，见下一篇。

4. 从 ROS 到模型槽位

下发路径在 real_env.step：单臂时左臂目标拷贝 _reset_position_left0，右臂目标等于策略的 7 维。可选的关节滤波在发布前作用于 7 维指令。复位函数 puppet_arm_publish_continuous 把两臂从当前姿态插到复位，避免上电瞬间阶跃。

5. 服务端一次 infer 的变换顺序

policy_config.create_trained_policy 把训练配置里的变换拆成输入链和输出链。推理输入链是：

  1. InjectDefaultPrompt — 写入螺丝分拣句子。
  2. CobotSingleArmInputs — 相机槽位与 mask；adapt_to_pi=False，关节符号不翻转。
  3. Normalize — 分位数，state 与（若存在的）actions 一起缩放。
  4. ResizeImages(224, 224) — 客户端已是 224，这里再保证一次。
  5. TokenizePrompt(discrete_state_input=True) — π0.5 把 state 写成 256 档文本。
  6. PadStatesAndActions(32) — 7 维补到模型宽度。

采样用 sample_actions，默认 10 步。输出链反过来：

  1. Unnormalize — 分位数逆变换，只作用于有统计量的前 7 维。
  2. AbsoluteActions — 前 6 维加回当前 state，夹爪不动。
  3. CobotSingleArmOutputs — 截断到前 7 维。
  4. OptimizeActionsQP — 固定参数 dt=0.033，w_data=1，w_acc=100，w_jerk=100。
$$ \min_x\ \frac{w_d}{2}\|x-a\|^2 + \frac{w_a}{2}\|D_2 x\|^2 + \frac{w_j}{2}\|D_3 x\|^2 $$

\(D_2,D_3\) 是沿时间的二阶、三阶差分，对应加速度和加加速度。\(dt=0.033\) 对齐 30 Hz。这一步在绝对关节空间里做，所以平滑的是机器人真正要跟踪的轨迹，不是归一化噪声。

欧拉步与训练同一速度场：

$$ x \leftarrow x - \frac{1}{10} v_\theta(x, o, t), \qquad t: 1 \to 0 $$

KV cache 使 10 步里的视觉编码不重复。计时写在返回字典的 policy_timing.infer_ms，只覆盖采样本身，不含 WebSocket。

6. 30 Hz 控制环里谁在等待

Runtime._run_episode 的一拍：

  1. 取观测（ROS 同步，可能阻塞到下一帧相机）。
  2. PolicyAgent 调用 Broker。只有缓存用尽才发 WebSocket。
  3. apply_action 发布关节目标。
  4. 若本拍耗时小于 \(1/30\) 秒则 sleep，否则打印超时。

因此模型延迟被摊到 32 拍上。若 infer_ms 约为 80，则平均每拍只增加 \(80/32=2.5\) ms，30 Hz 仍赶得上。代价是这 32 拍里相机变化不会影响已发出的指令。螺丝入孔这类末端精度，后续用 RTC 在块还没执行完时就生成下一块，并用前缀约束接上。

安全边界。 Episode 不会因为任务完成自动停（is_episode_complete 恒为 False），只受 max_episode_time_s=600 限制。急停靠机器人自身的硬件开关和 ROS 层。策略进程崩溃时客户端应停在最后一条关节指令，不要把未初始化数组发出去。

7. 一拍的数值账

普通 SFT 服务加载的是 pi05_cobot_screw_sorting_single，模型视野仍是 50。客户端 main.py 的 broker 只执行 32 拍。下面把「为什么是这几个数」算开。

7.1 开环窗口有多长

30 Hz 下，32 拍是 \(32/30\approx 1.07\) 秒，模型多预测的 18 拍是再往后 \(0.60\) 秒。这 0.60 秒的动作被丢掉，用来换一次新的图像。若 infer_ms=80，则 32 拍里只有 1 拍在等网络，其余 31 拍读的是已经到本地的数组。摊到每拍是 \(80/32=2.5\) ms，小于控制周期 33.3 ms。若推理涨到 400 ms，单次调用已经超过 32 拍的墙钟（\(32\times 33.3\approx 1067\) ms 才是整段预算，400 ms 仍放得下），但块与块之间会有一段完全不看新图像的时间，长度等于这 400 ms 里手臂已经走掉的拍数 \(d\approx 400/33.3\approx 12\)。普通 broker 不把这 12 拍交回服务器，所以接缝没有约束。这正是 RTC 要补的量。

7.2 绝对化为什么通常让第一拍靠近当前关节

训练目标的第 0 行是 \(\delta_0 = q_t - s_t\)。示教里 \(q_t\) 往往就是这一拍要跟踪的目标，和当前关节很近，所以 \(\delta_0\) 的前 6 维在数据里集中在 0 附近。推理

$$ \hat q_0 = \hat\delta_0 + s_{\mathrm{now}}. $$

若网络把 \(\hat\delta_0\) 预测成 0，右臂第一拍停在原地。夹爪不加 state：张开 0.9 经过分位数后是某个 \(\hat g\in[-1,1]\)，反归一化直接回到 0.9 附近，不会变成 \(0.9-s_6\)。若日志里第 0 拍肩关节相对当前值跳了 0.3 rad 以上，先查三件事：state 是不是 14 维双臂被切错、delta 掩码是不是在服务端又加了一次、norm stats 是不是绝对角而不是增量的分位数。

7.3 分位数的一轮整数

设肩关节增量的 \(q_{01}=-0.15\)、\(q_{99}=0.25\)，网络输出 \(\hat x=0\)（归一化区间的中点）。反变换

$$ \delta = \frac{0+1}{2}(0.25-(-0.15)+10^{-6}) + (-0.15) = 0.05. $$

中点不是 0 增量，而是两个分位的中点。示教增量分布左右不对称时，这是对的。若误用 z-score 的均值方差去解这个 \(\hat x\)，0.05 会变成别的数，肩会恒定偏一个角度。

7.4 QP 在 50 步上实际压的是哪一阶

无约束正规方程是 \((w_d I + w_a D_2^\top D_2 + w_j D_3^\top D_3)x = w_d a\)，这里 \(w_d=1\)，\(w_a=w_j=100\)。\(D_2\) 的一行是 \((1,-2,1)\)，作用在相邻三拍上。一个尖峰若只在第 \(k\) 拍高出邻拍 0.02 rad，\(\|D_2 x\|^2\) 大约是 \(0.02^2\) 量级，乘 100 后和数据项 \(\|x-a\|^2\) 同阶，所以优化器会削掉大约一半这种单拍尖峰，而不会把整段 1 秒的趋势拉平。\(dt=0.033\) 没有乘进 Hessian：惩罚的是「每拍差分」，不是 rad/s²。同样 0.02 rad 的跳变，在 30 Hz 是 \(0.02/0.033^2\approx 18\) rad/s²，在 50 Hz 是约 50 rad/s²。权重不随频率变，所以把同一 checkpoint 从 30 Hz 改到 50 Hz 播放时，QP 相对物理加速度会变松。

7.5 服务器不重算统计量

create_trained_policy 从 checkpoint_dir/assets/<asset_id> 读 norm_stats，不读训练机上后来又跑的 compute_norm_stats。asset_id 在普通配置里是 screw_sorting_single。若落地时把 repo 改成 screw_sorting_single_sft_ep280_v30_steam 或代码里 RTC 配置用的 screw_sorting_single_sft_ep279_annotated，服务端目录名必须跟着变。统计量描述的是 delta 之后的 7 维，换数据集而不换 stats，等价于用别人的 \(q_{01},q_{99}\) 做仿射。

附录 · 推理侧算法推导

A. 条件分布的采样如何变成关节指令

SFT 训练得到速度场 \(v_\theta(x,o,t)\)，其积分核在 \(t=0\) 的边缘近似示教条件分布 \(p(a\mid o)\)。一次 infer 做的是：

$$ o \mapsto \hat a = g^{-1}\big(\mathrm{ODESolve}(v_\theta, \varepsilon, o)\big) $$

其中 \(g\) 是训练时的复合变换：delta、分位数、pad。\(g^{-1}\) 必须严格反序，否则 \(g^{-1}\circ g \neq \mathrm{id}\)。代码把逆变换写成输出链：先反 pad 的统计（无统计量的维保持），再加 state，再切 7 维，最后 QP。QP 不是 \(g\) 的逆，它是执行前的正则，训练分布里没有这一项。所以日志里若比较「模型原始输出」和「下发指令」，差的是加速度惩罚，不是归一化 bug。

B. 分位数逆变换

训练

$$ \hat x = 2\cdot\frac{x-q_{01}}{q_{99}-q_{01}+\epsilon}-1 . $$

推理

$$ x = \frac{\hat x+1}{2}\,(q_{99}-q_{01}+\epsilon)+q_{01} . $$

state 与动作共用各自的 \(q_{01},q_{99}\)。delta 在归一化之前计算，因此统计量描述的是「相对当前姿态的增量」的分位数，不是绝对关节角的分位数。把绝对角的统计量拿来反归一化 delta，指令会偏出一个常量。

C. 绝对化为什么用当前 state，而不是 chunk 内部差分

训练目标是 \(\delta_k = q_{t+k}-s_t\)，\(s_t\) 是该样本时刻的观测。推理时机器人停在 \(s_{\text{now}}\)，网络吐出的 \(\hat\delta_k\) 是相对这个新起点的。还原式

$$ \hat q_k = \hat\delta_k + s_{\text{now}},\quad k=0,\ldots,H-1 $$

使 \(\hat q_0\) 接近当前关节（若网络预测的第一步增量接近 0）。这就是开环块开头不跳变的原因。夹爪维 mask 为 False，\(\hat q_{k,6}=\hat a_{k,6}\) 直接是开合度。

D. QP 平滑的正规方程

无约束时目标

$$ J(x)=\frac{w_d}{2}\|x-a\|^2+\frac{w_a}{2}\|D_2x\|^2+\frac{w_j}{2}\|D_3x\|^2 $$

梯度置零得到

$$ \big(w_d I + w_a D_2^\top D_2 + w_j D_3^\top D_3\big) x = w_d a . $$

代码用 OSQP 解这个二次规划，并对每个动作维独立求解。w_acc=w_jerk=100 相对 w_data=1 很强，轨迹会明显变圆。末端对孔时若显得发黏，先把这两个权重降下来，而不是加大 flow step。\(dt\) 本身不进 Hessian（差分矩阵按步索引），但注释用它标记控制周期；加速度的物理量纲若要和在线 RL 的 acc/jerk 惩罚对齐，需要把差分乘 \(1/dt^2\)、\(1/dt^3\)。当前 SFT 输出链的 QP 按索引差分，不是按秒。

E. 开环视野与执行视野

模型条件于时刻 \(t\) 的观测 \(o_t\)，生成 \(\hat q_{t:t+50}\)。客户端只执行 \(\hat q_{t:t+32}\)，然后在 \(t+32\) 重新观测。被丢掉的 18 步是「若世界不变，模型原本还想做的动作」。重新推理用新图像替换了这段外推。延迟 \(d\) 拍期间机器人仍在执行旧块，新块的前 \(d\) 步与旧块尾部没有等式约束，所以块边界可能有一阶不连续。RTC 把这个不连续写成带权最小二乘，加进 ODE 的漂移项。

F. 离散 state 文本的信息量

256 档均匀切在归一化区间 \([-1,1]\)。量化误差最大 \(1/256\)。对已经分位数归一化的关节，这大约是 \(q_{99}-q_{01}\) 的 \(0.4\%\)。夹爪同样被写进文本。动作专家看不到连续 state 向量，它只通过语言 token 的交叉注意力得知本体。因此 state 的归一化必须和分词用的是同一份 \(\hat s\)：先分位数，再 digitize。顺序反了，文本里的整数和训练分布对不上，语言条件就废了。

G. 和训练文档、RTC、RLT 的接口

本页消费训练文档的两样东西：EMA 权重，以及随 checkpoint 保存的 norm_stats。它产出的是绝对关节块。RTC 客户端在此之前把「上一块还没执行的后缀」作为 prev_action 送回 guided_inference。RLT 的 Machine A 复用同一条 VLA 采样，额外返回图像 prefix 压出来的 \(z_{\text{rl}}\)，在线 actor 再输出一条更短的 10 步修正。螺丝分拣的 prompt、相机槽位和 7 维右臂在四篇文档里保持同一契约。
