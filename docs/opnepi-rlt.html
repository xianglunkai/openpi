1. 系统总图

2. 离线 RL token

结构在 src/openpi/models/rl_token.py。螺丝单臂的两份配置：

编码器用可学习查询 \(q\in\mathbb R^{1\times 2048}\) 对 prefix 做两层交叉注意力，解码器用长度为序列的查询去读这个 token，重建被 stop-gradient 的 prefix。训练步在 scripts/train_rlt.py 的 RLTTrainModel.compute_rlt_loss：

$$ \mathcal L_{\text{ro}} = \mathrm{MSE}\big(\mathrm{Dec}(\mathrm{Enc}(\mathrm{sg}(h))),\, \mathrm{sg}(h)\big) $$
$$ \mathcal L = \mathcal L_{\text{ro}} + \alpha\, \mathcal L_{\text{flow}} $$

\(h\) 只取图像 token（image_only=True），语言 token 不进重建。padding 和缺相机（左腕）由 prefix_mask 从 MSE 里去掉。\(\alpha=0\) 时 VLA 只做一次前向抽 embedding，优化器过滤 .*rlt_module.*。\(\alpha>0\) 时同一次 compute_loss_with_prefix 同时给出流匹配损失和 embedding，避免两次 backbone。

输入维 2048。 RLTokenConfig.input_dim 注释写的是 Gemma 2B 的 prefix 宽。本配置把 embed_dim 也设成 2048，于是没有额外的 input/output 投影，token 和 VLA 隐层同宽。在线 yaml 的 z_dim: 2048 必须和这里一致。

3. Machine A 怎么同时吐动作和 token

scripts/server_rlt_policy.py 加载 VLA 与 rlt_module，对一张观测返回参考动作块和 \(z_{\text{rl}}\)。在线 rollout 把它当作 Machine A。螺丝脚本是 examples/mobile_aloha_AgileX/run_server_screw_sorting_single_rlt.sh，指向两阶段 checkpoint 的 step 9999，配置名却传了 pi05_cobot_screw_sorting_single_joint_vla_rlt。落地时配置名必须和 checkpoint 的 rlt_alpha、权重布局一致，不要混用两阶段目录和联合配置。

推理侧编码同样 image_only。\(z_{\text{rl}}\) 在一个 chunk 的执行期间保持不变，直到下一次观测。这就是 actor 能做成小 MLP 的原因：视觉已经在 2048 维里。

4. 在线环：谁在什么时候动右臂

动作在进 actor 之前变成 delta chunk，再用与 SFT 相同的分位数映到 \([-1,1]\)。统计文件是 configs/tasks/screw_sorting/stats/norm_stats_delta.json。前 6 维相对 proprio 做差，夹爪保持绝对，然后

$$ \tilde a = 2\cdot\frac{a-q_{01}}{q_{99}-q_{01}+\epsilon}-1 . $$

网络内部的动作因此和 π0.5 的归一化空间同尺度。算加速度惩罚时再反归一化回绝对关节，\(dt=1/30\)。

5. 在线目标

Critic 是 twin Q。目标用 TD3 式的确定性下一步动作，自举按真实步数而不是固定 chunk 长（build_td_target）：

$$ y = R_{\gamma} + (1-d)\,\gamma^{n}\, \min(Q_{\bar 1}, Q_{\bar 2})(z', p', \mu_{\theta}(z',p',\mathrm{ref}')) $$
$$ \mathcal L_Q = \|Q_1-y\|^2 + \|Q_2-y\|^2 $$

\(n=\) actual_steps，\(R_\gamma\) 是 chunk 内奖励的折扣和。target_q_clip=100，gamma=0.99，目标网络 \(\tau=0.005\)。L2C2 项默认权重 0。

Actor 损失在 trainer.update_actor，螺丝配置的系数为 bc_weight=3（warmup 与 online 相同）、q_weight=1、delta_weight=0、delta_acc_weight=delta_jerk_weight=500：

$$ \mathcal L_{\pi} = 3\,\mathbb E\big[\textstyle\sum_{c,a}(\mu-a^{\text{bc}})^2\big] - \mathbb E\big[\min_i Q_i(z,p,\mu)\big] + 500\,\mathbb E\|D_2 q\|^2 + 500\,\mathbb E\|D_3 q\|^2 $$

\(D_2=[1,-2,1]\)、\(D_3=[1,-3,3,-1]\) 作用在反归一化后的前 6 个关节上，夹爪不进这两项。compute_abs_chunk_acc_jerk_penalty 先除以 \(dt^2\)、\(dt^3\) 得到物理加速度，再乘回 \(dt^4\)、\(dt^6\)，和 acc_weight 相乘后正好剩下「权重 × 差分平方」。所以 yaml 里的 500 就是加在索引差分上的系数，\(dt=1/30\) 已经约掉。delta_weight=0 时，和参考增量对齐的那一项不进损失。

bc_reduction: sum 表示先对 \(10\times 7\) 维求和再对 batch 取均值，所以 BC 的数值大约是「均值误差 × 70」。参考块以概率 0.5 被整段置零（reference_dropout_prob），迫使 actor 在没有 VLA 提示时仍能靠 \(z\) 和本体出动作。bc_imitate_human: false 时，BC 目标始终是 VLA 的 ref_chunk，即使某步来自人工。打开该开关后，人工步的目标改成实际执行的 action_chunk。

高斯策略的标准差是常数 0.05，不学习。训练时可以从噪声采样探索；yaml 里 actor_deterministic: true，部署用均值。Actor 每 2 次 critic 更新才更新一次。

6. 可落地步骤

  1. 先有一份螺丝 SFT

    按 SFT 训练文档，在 screw_sorting_single_sft_ep280_v30_steam 上跑 pi05_cobot_screw_sorting_single。两阶段 RLT 的权重路径指向该实验的 step 20000。没有这份权重就不要把 rlt_alpha 设为 0：冻结一个随机初始化的 VLA，token 学到的是噪声表征。

  2. 把 RLT 配置的 repo_id 改成同一数据集

    pi05_cobot_screw_sorting_single_two_staged_rlt 与联合配置都仍写着短名 screw_sorting_single。和 SFT 一样改成全名，并单独算一份 norm stats 到各自的 assets_dir。变换矩阵（两路相机、delta mask (6,-1)、同一句 prompt）不要改。

    uv run scripts/compute_norm_stats.py --config-name pi05_cobot_screw_sorting_single_two_staged_rlt
uv run scripts/train_rlt.py pi05_cobot_screw_sorting_single_two_staged_rlt \
  --exp-name=pi05_cobot_screw_sorting_single_two_staged_rlt

    日志里应看到 rlt_loss 下降，且 vla_loss 不出现（α=0）。若出现 vla_loss，说明 α 没读到 0。

  3. 用 RLT 服务替换普通 serve_policy

    uv run scripts/server_rlt_policy.py \
  --port 8000 \
  --shared_prefix_inference \
  --default_prompt 'Please sort and return the silver screws in the grey box to their proper places.' \
  --checkpoint_dir <两阶段实验>/9999 \
  --config pi05_cobot_screw_sorting_single_two_staged_rlt \
  --rtc-warmup-s 25 10 \
  --rtc-warmup-d 6 7

    仓库里的 run_server_screw_sorting_single_rlt.sh 把两阶段目录配上了联合配置名 pi05_cobot_screw_sorting_single_joint_vla_rlt。服务前改成和 checkpoint 同名的配置，避免 token 宽度和 α 的元数据对不上。

    客户端或 rollout 发来与 SFT 推理相同的右臂观测。返回里除了动作还有 z_rl。用一条静止观测打两次，\(z_{\text{rl}}\) 应相同；挡住高位相机，\(z_{\text{rl}}\) 应明显变化。这是 token 是否看图的最低检查。

  4. 用示教先灌满 replay，再让 learner 预热

    rlt_online_rl/run_build_warmup_journal.sh 能从 LeRobot 示教造 warmup journal。把 DATASET_ROOT 指到 screw_sorting_single_sft_ep280_v30_steam。在线 yaml 要求 warmup_min_size: 1200，然后 warmup_post_collect_updates: 50000。在这 5 万次更新完成、ready_for_online 为真之前，右臂只执行 VLA 参考块。

  5. 按 yaml 起 Machine B 和真机 rollout

    入口在 rlt_online_rl/run_start_machineB.sh、run_start_rollout.sh。关键开关已经在螺丝配置里：

    action_dim: 7
chunk_len: 10
control_frequency_hz: 30
vla_chunk_exec_horizon: 50
rtc_execution_horizon_vla: 20
rtc_execution_horizon_rl: 10
rtc_inference_delay: 7
use_rtc: true
task_mode: full_task

    复位姿态用的是 real_env 里右臂那组 _reset_position_right0（7 个数，末位夹爪 0.09）。人只在回合之间切换阶段。关键相位的人工信号未开时（enable_human_override: false），不要指望中途接管会写进 BC 目标。

  6. 看四条数再决定要不要放开 Q

    Learner 日志有 critic_loss、actor_loss、bc_penalty、actor_q。warmup 阶段 BC 应先降。Q 的绝对值被 clip 到 100。若 actor_q 顶满而真机成功率下降，是 Q 过估计把动作推出了 VLA 流形；保持 bc_weight=3，不要先把 q_weight 加大。加速度项已经是 500，关节若发黏，先降 delta_acc_weight，它直接加在绝对关节的二阶差分上。

7. 数量级核对

上一节的公式如果只看符号，BC、Q 和加速度谁在主导并不清楚。下面用螺丝 yaml 的系数和张量形状算一次。

7.1 \(z_{\mathrm{rl}}\) 压掉了多少 token

三路相机槽各 256 个 SigLIP patch，共 768 个图像 token，宽 2048。RLTTrainModel 的 prefix_seq_len 默认也是 768，和「只重建图像、不重建语言」一致。左腕 mask 为假的那 256 个不进 MSE 分母。有效 token 约 512。一个查询把它压成 \(1\times 2048\)。压缩比按元素个数是 \(512\times 2048 / 2048 = 512\) 倍。重建损失只要求这一个向量能通过两层交叉注意力还原被 stop-gradient 的 \(h\)，不要求它线性可逆。任务句子不在 \(h\) 里。螺丝分拣只有一句固定 prompt，换场景不换句子时，\(z\) 的变化全部来自图像。挡住高位相机而 \(z\) 几乎不动，说明编码器在用腕部或者在用位置编码的常数项，token 没有接上视觉。

7.2 α=0 时 VLA 的哪些数允许变

可训练过滤是路径匹配 .*rlt_module.* 的 nnx.Param。动作专家、SigLIP、时间 MLP 都不在优化器里。EMA 被设成 None，checkpoint 里的 VLA 叶子应与 step 20000 的 SFT 逐元素相同。若服务端动作块和当时的 SFT 推理差一个明显偏置，先对这两份 params 做叶子级对比，而不是先怀疑在线 actor。联合配置 \(\alpha=1\) 则相反：流匹配梯度进 VLA，重建梯度仍被 stop_gradient 挡住。同一份螺丝数据上，两阶段保住参考块，联合训练会把参考块一起挪走，warmup journal 必须重做。

7.3 BC 和 Q 谁更大

bc_reduction=sum，\(C=10\)，\(A=7\)。设每一维误差是 0.1（归一化动作，大约是 \([-1,1]\) 区间的 5%），

$$ \|\mu-a^{\mathrm{bc}}\|^2_{\mathrm{sum}} = 70 \times 0.01 = 0.7,\qquad 3\times 0.7 = 2.1. $$

Q 被裁到 \([-100,100]\)，\(q\_weight=1\) 时 \(-Q\) 的一项最大能到 100，比 2.1 大一个数量级。所以一旦 critic 饱和在裁剪边界，BC 拉不回来。warmup 的 5 万次更新若把 target_q_mean 推到几十，在线阶段右臂会离开 VLA 参考，即使 bc_weight 仍是 3。

参考 dropout 只作用在 actor 的输入上。update_actor 把置零后的 ref 送进 actor_mean，BC 目标在 bc_imitate_human=false 时仍是原始的 batch["ref_chunk"]，不是置零后的那份。概率 0.5 的那些样本要在「看不见参考块」的条件下，把输出做回 VLA 的参考。它不是在学输出 0。若把目标也一起置零，策略会被拖向分位数中点 \((q_{01}+q_{99})/2\)，那是另一套损失，当前代码没有这么写。

7.4 自举步数差一拍，折扣差多少

\(\gamma=0.99\)。chunk 名义长度 10，RTC 若提前截断到实际执行 \(n=4\)，

$$ \gamma^{10}\approx 0.904,\qquad \gamma^{4}\approx 0.961. $$

用错成 \(\gamma^{10}\) 时，同样的下一步 Q 被少乘了大约 0.06。若 \(Q\approx 20\)，目标低了约 1.2，每步都有。代码用 actual_steps 做指数，就是为了避免把未执行的 6 拍也折扣掉。step_trace_stride: 2 还会让转移窗口不是严格的 chunk 边界，\(n\) 必须来自窗口里真实写入的拍数，不能写死 10。

7.5 加速度权重 500 在损失里剩多少

compute_abs_chunk_acc_jerk_penalty 先算物理量 \(a=D_2q/dt^2\)，再乘 \(dt^4\)。\(dt=1/30\) 时 \(dt^4 = 1/30^4 \approx 1.23\times 10^{-6}\)，乘 500 约 \(6.2\times 10^{-4}\)。它乘的是 \(\mathbb E[a^2]\)。换一种写法，\(dt^4\) 与 \(1/dt^4\) 相消，损失里就是 \(500\cdot\mathbb E[(D_2 q)^2]\)，\(D_2 q\) 的单位是弧度每拍，不是 rad/s²。相邻三拍若差出 0.01 rad 的二阶差分，这一项约 \(500\times 10^{-4}=0.05\)，比第 7.3 节里 2.1 的 BC 小。差分到 0.05 rad 时，\(500\times 0.0025=1.25\)，和 BC 同阶。所以 500 并不会把 0.01 rad 的弯抹平，它开始起作用的尺度是几百分之一个弧度的每拍二阶差。SFT 输出链的 QP 用的是另一套权重（\(w_a=100\) 且在绝对关节的后处理里），两边不会自动配平。

7.6 在线 actor 看见的 VLA 是哪一种 RTC

yaml 打开了 use_rtc: true，VLA 的执行视野 20、延迟 7，RL 块视野 10。Machine A 若仍走 guided_inference，参考块是测试期引导采样，不是第 RTC 文档 7.1 节那种钉死前缀的采样。actor 的 BC 目标跟着这个参考走。把 Machine A 换成 pi05_cobot_screw_sorting_single_rtc 的 checkpoint 而不改采样函数，BC 会去模仿一个训练分布之外的样本。在线环和离线 token 训练可以分开换，但参考块的生成方式要和那个 checkpoint 的 rtc_max_delay 一致。

附录 · 算法推导

A. 为什么要压缩 prefix

π0.5 的图像 token 序列长度是相机数乘以 SigLIP patch 数，两路有效相机大约数百 token，宽 2048。在线 critic 若直接吃这条序列，每步控制都要回传大 Transformer，30 Hz 上不现实。RL token 用一个查询向量做交叉注意力池化：

$$ z = \mathrm{Attn}(q,\, hW_K,\, hW_V) \in \mathbb R^{1\times 2048} $$

两层交叉注意力加 MLP（mlp_ratio=4，8 头）给出足够的非线性，但参数量相对 Gemma 2B 可以忽略。重建损失强迫 \(z\) 保留能还原 \(h\) 的信息。因为目标是 \(\mathrm{sg}(h)\)，编码器不会通过改 VLA 来降低 MSE。信息瓶颈因此只在 token 侧。

重建不是动作损失。一个能完美重建图像 token 的 \(z\) 仍可能对「螺丝相对夹爪的相位」不敏感，如果这些信息主要在被丢掉的语言 token 里。本实现 image_only=True，任务句子不进 \(z\)。螺丝分拣只有一句固定 prompt，这个省略可接受；换任务而不换图时，\(z\) 不会变，区分任务的责任留在 VLA 参考块里。

B. α 的两种训练动力学

\(\alpha=0\)：参数分割是硬的。优化器状态只为 rlt_module 创建，VLA 叶子不在 apply_updates 里。EMA 被关掉，是因为 checkpoint 推理读的是 ema_params；若对冻结权重仍做 \(0.99\bar\theta+0.01\theta\)，而 \(\theta\) 在数值上又被别的路径碰过，服务端会看到一份漂过的 VLA。代码注释把这件事写死了。

\(\alpha=1\)：总损失 \(\mathcal L_{\text{ro}}+\mathcal L_{\text{flow}}\)。流匹配梯度进 VLA，重建梯度不进 VLA（stop-gradient 仍在）。于是 VLA 按示教更新，token 追踪移动中的 prefix。这比两阶段更可能让 \(z\) 和动作头一起漂移，在线阶段必须重新收集 warmup。两阶段的好处是 Machine A 的参考块与已经验证过的 SFT 相同。

C. 在线 MDP 为什么按 chunk 而不是按拍

策略输出的是长度 \(C=10\) 的动作块，执行 \(n\le C\) 拍后才有下一次决策（RTC 可能提前截断）。把这 \(n\) 拍收成一个转移 \((z,p,a,r_{1:n},z',p')\)，贝尔曼方程用 \(n\) 步回报：

$$ Q(z,p,a) = \mathbb E\Big[\sum_{k=0}^{n-1}\gamma^k r_{k+1} + \gamma^n \min_i Q_i(z',p',\mu(z',p',\mathrm{ref}'))\Big] $$

若误用 \(\gamma^C\) 而实际只执行了 \(n<C\) 步，自举会把未来折扣打得过重，Q 偏小。所以 actual_steps 进了目标。Twin-min 与缓慢跟踪的目标网络是 TD3 的过估计控制；这里没有目标策略平滑噪声，下一步动作就是 actor 均值再 clip 到 \([-1,1]\)。

D. BC 项是在流形上的锚

纯最大化 \(Q\) 的 actor 可以走出 VLA 从未演示过的关节速度，Q 在那里是外推。对参考块的平方惩罚把 \(\mu\) 拉回 \(\pi_{\text{SFT}}\) 的输出附近。系数 3 相对于 Q 的量级：BC 是 70 维求和，每维误差 0.1 时惩罚约 \(3\times 0.7=2.1\)；Q 被 clip 在 100 以内，\(q\_weight=1\) 时 Q 项可以更大。因此后期若 Q 可信，策略会离开参考；若 Q 不可信，大的 BC 仍占优。参考 dropout 0.5 只把输入里的 ref 整段置零，BC 目标仍是原来的 VLA 块。一半样本必须在没有参考输入时仍输出那条参考，这样 actor 不能退化成「把输入原样抄出来」，VLA 抖动时它仍有一条由 \(z\) 和本体决定的输出。

E. 加速度与加加速度

反归一化并加回 proprio 的前 6 维后，二阶、三阶差分与 SFT 输出链的 QP 模板相同。物理量 \(a=D_2q/dt^2\)、\(j=D_3q/dt^3\) 只用于日志。进损失的是

$$ 500\cdot\mathbb E[(D_2 q)^2] + 500\cdot\mathbb E[(D_3 q)^2] = 500\,dt^{4}\,\mathbb E[a^2] + 500\,dt^{6}\,\mathbb E[j^2] $$

两边相等，因为 \(dt^4\) 与 \(1/dt^4\) 相消。这是可微惩罚，直接进 actor 梯度。SFT 推理末尾的 QP 是另一回事，它不产生梯度。两者叠在真机上时，在线策略已经变圆，Machine A 路径上的 QP 会再圆一次，末端更黏。螺丝 yaml 的 delta_weight=0，相邻增量相对参考增量的均方误差不进损失，平滑只来自 acc/jerk。

F. 干预数据怎么进缓冲区

README 与 trainer.py 的分工是：人工介入的步，在写入 replay 之前可以把 ref_chunk 对应行换成实际执行；训练时若 bc_imitate_human 为真，则按 source_chunk 的 HUMAN/MIXED 掩码选择 BC 目标。当前螺丝配置两个开关都偏保守：enable_human_override: false，bc_imitate_human: false。因此默认在线目标是「像 VLA，同时 Q 更高，同时更平滑」，不是「模仿操作员的纠正」。要做干预学习，两处都要打开，并且只在回合边界改变控制源，否则 chunk 窗口会被标成 MIXED，BC 目标在窗内按步切换。

G. 四篇文档合成的一条原理

示教分布 \(p_{\text{demo}}(a\mid o)\) 由 SFT 的流匹配速度场表示，数据是 280 条 30 Hz 的右臂螺丝轨迹。推理把速度场积成绝对关节，并用 QP 限制单块光滑。RTC 在积分漂移里加入对已承诺前缀的加权拉力，处理 Cobot Magic 上不可避免的推理延迟。RLT 把同一速度场的视觉条件 \(h(o)\) 压成 \(z\)，再在 \(z\) 上做带 BC 锚的 twin-Q 策略改进。在线策略不替换 VLA 的采样器，它输出的是一条短块，经 RTC 接在 VLA 长块的时间轴上。所以改坏 \(z\) 的重建、或让 actor 的 BC 权重变成 0，都会让右臂离开 screw_sorting_single_sft_ep280_v30_steam 所支撑的那片关节流形。
