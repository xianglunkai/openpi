HIL 成功数据抽取

螺丝分拣的人在回路录制会把策略帧和人手帧写进同一条情节。抽取脚本只留下按 s 成功的数据，并按情节形态切开：整段都是自动的成功原样复制；成功但中途有人手的，只保留连续的干预片段。按 f 和超时都不进新数据集。

1. 从录制到新数据集

2. 录的时候写了什么

一帧能不能说明「这条情节成功了」？不能。is_intervention 只表示这一帧是策略还是人手。整段都是 0，只说明没有人碰，不能说明按过 s。超时、按 f、按右箭头，从帧上看可以和一次自动成功一模一样。

所以结果另写在 meta/hil_outcomes.jsonl。每一行是数据集保存之后的情节编号和结束状态。编号用的是 LeRobot 分配的 episode_index，不是运行时那个会因重录而重复的计数。

{"episode_index": 0, "status": "success"}
{"episode_index": 1, "status": "failure"}
操作写入的 status抽取时
ssuccess，奖励 1进入候选
ffailure，奖励 0整条丢掉
超过 max_episode_time_s同样写成 failure整条丢掉
左箭头 / r清空缓冲，不落盘，不写 jsonl没有这条情节
右箭头、环境结束、Escnext_episode / end / abort_all不是 success，丢掉
空格 / i，或 SpaceMouse 介入不结束情节；该帧 is_intervention = 1用来切片段
两条写入路径写的是同一份文件。 机器人客户端走 tcp://127.0.0.1:8765 时，由 lerobot_recorder_service.py 在 save_episode() 之后调用 append_hil_outcome。不走远程录像时，RuntimeRTCHil._finish_lerobot_episode 自己写。重录清空缓冲，不会留下半条结果。

3. 四条情节怎么切

先读 hil_outcomes.jsonl。状态不是 success 的情节直接跳过，里面的人手片段也不要。成功的情节再看 is_intervention > 0.5 的连续段。

成功情节里的自动帧不会和人手帧拼在同一条新情节里。 一旦这条成功里出现过干预，自动部分全部留在源数据里。新数据集里，auto_success 的每一帧 is_intervention 写成 0，intervention 的每一帧写成 1。

4. 怎么跑

在仓库根目录执行。脚本会激活 .venv，并要求源目录里已经有 meta/info.json 和 meta/hil_outcomes.jsonl。

bash examples/mobile_aloha_AgileX/run_extract_hil_lerobot_subset.sh \
  /data/huggingface/lerobot/openpi_hil/hil_screw_sorting_20261029_171747

第二个参数是输出目录。不写时，输出放在源目录旁边，目录名加上 _auto_and_intervention。脚本固定带 --overwrite，同名目录会被换掉。只要更长的片段时，先设 MIN_FRAMES。

MIN_FRAMES=8 bash examples/mobile_aloha_AgileX/run_extract_hil_lerobot_subset.sh \
  /path/to/src_dataset \
  /path/to/output_dataset

只看计划、不写文件时，直接跑模块并加上 --plan-only。没有 hil_outcomes.jsonl 时，计划仍会打印每条情节的长度和干预帧数，然后停住。

python -m examples.mobile_aloha_AgileX.extract_hil_lerobot_subset \
  --src /path/to/src_dataset \
  --plan-only

  1. 核对结果文件

    源数据集的 meta/hil_outcomes.jsonl 里，按过 s 的情节是 "status": "success"。超时和 f 都是 failure，不要改成成功。

  2. 先看计划

    终端会按源情节打印长度、干预帧数、fully_auto、状态，以及这条会留下几段。汇总行给出纯自动成功条数、干预段数和总帧数。

  3. 写出新数据集

    跑 shell 脚本。它调用同一个模块，带上 --output 和 --overwrite。写完后到输出目录的 meta/hil_extract.jsonl 核对每条新情节的来源。

5. 新数据集里有什么

输出仍是 LeRobot v2.1，use_videos=False。图像从源 parquet 里的 PNG 解码成 RGB 再写入。源特征里如果有视频列，脚本会直接停住。时间戳、frame_index、episode_index、index、task_index 由 LeRobot 在保存时重写，不从源帧拷贝。

新情节字段含义
observation.state / action源帧里的向量，float32
observation.images.*对应相机的 RGB 帧
is_intervention这条新情节的种类：自动成功为 0，干预段为 1
task源情节 episodes.jsonl 里的任务字符串

meta/hil_extract.jsonl 每一行对应一条新情节：

{"episode_index": 0, "kind": "auto_success", "source_episode": 2,
 "source_start": 0, "source_end": 402, "length": 402, "task": "..."}
{"episode_index": 1, "kind": "intervention", "source_episode": 4,
 "source_start": 80, "source_end": 210, "length": 130, "task": "..."}

source_start 含、source_end 不含。同一条源情节可以贡献多条 intervention。新情节之间不再保留原来夹在中间的自动帧。

6. 旧数据为什么抽不了

2026-10-29 那份 hil_screw_sorting_20261029_171747 的每一帧都有 is_intervention，所以干预段数得出来。当时结束一条情节只在终端打印 status=，meta/episodes.jsonl 里只有编号、任务和长度。没有 hil_outcomes.jsonl 时，超时、按 f、按 s 无法从帧里区分，脚本拒绝写出新数据集。

这份旧数据不会被自动补上结果。 之后新录的数据会在保存时写 meta/hil_outcomes.jsonl。对那之后的目录，直接运行本页的 shell 脚本即可。
