WALL-WM 算法笔记

按数据进入模型的顺序写。每一节先说明这一步在解决什么，再给出符号和公式。

论文：WALL-WM: Carving World Action Modeling at the Event Joints，X Square Robot，arXiv:2606.01955。公式编号与论文第 3–6 节一致。

0. 用一个任务看问题

任务是：把桌上的杯子放进盒子。人用一句话就能说完。相机看到的是一段连续画面。控制器需要的是一串很密的末端位移。

这三样东西的时间单位不一样。

语言

说的是完整动作：伸手、抓住、抬起、放下。

视频

画面连续变化，接触发生在很少的几帧里。

动作

控制周期很短，一条指令只覆盖零点几秒。

常见做法是按固定长度切块。比如每次预测未来 1 秒的动作，条件只有当前画面和整句任务。切出来的那一秒，可能正好卡在「手指刚碰到杯壁」。字幕却仍是「把杯子放进盒子」。模型最容易学到的是这一小段里的局部相关，而不是「抓住」这个完整动作。

WALL-WM 先把演示切成语义上完整的事件，再让字幕、视频和动作描述同一段物理过程。上面这个任务可以切成五段：

  1. 手臂移到杯子旁边。
  2. 夹爪合上。
  3. 把杯子抬离桌面。
  4. 移到盒子上方。
  5. 松开，杯子落入盒子。

每一段长度不必相同。合上夹爪可能只有零点几秒，移动可能要两秒。模型一次学习一段，而不是一次学习固定的 30 个控制步。

后文所有设计都为了保住这件事。视频模型原来就会「按一句描述生成一段画面」。训练动作时不能把这个能力冲掉。所以动作网络只读取视频特征，动作损失不更新视频网络。

1. 模型在估计什么

记一条事件为 e。模型估计的条件分布是

\[ p_{\theta}(V_e, a_e \mid V_0, s, c_e) \]

给定当前画面、当前本体状态和这句事件描述，同时生成这段事件的未来视频和末端轨迹。

符号含义
\(V_0\)当前时刻每个相机的一帧画面。论文里的部署例子是 3 个相机。
\(s\)当前本体状态。它是绝对量，用来说明机器人现在处于什么构型。
\(c_e\)只描述这一段事件的字幕，例如「合上夹爪」。
\(V_e\)从当前帧往后、与这段事件等长的多相机视频。
\(a_e\)同一时间段里的末端轨迹。长度随事件变化。

视频和动作都不是一次回归出来的。两边都用 flow matching：从噪声出发，沿一条直线逐步走回干净的视频潜变量和干净的轨迹。第 4 节把这条直线写清楚。

2. 数据

训练集不是单一机器人的成功演示。论文按「看不看得到动作、视角像不像真机」分成四类，中间再加入接触失败和人工接管。

来源用来学什么缺什么
互联网视频物体外观和时间上的动态。文中包含约 120 万条 OpenVID 切片，以及 HD-VILA 等。没有机器人动作。
第一人称人类视频Ego4D、EPIC-KITCHENS 里的手部操作几何。不能直接当成关节指令。
无机器人的手持采集头戴相机加一对手持夹爪。夹爪外形与真机末端一致。6 自由度轨迹用部署机器人的 URDF 做逆运动学，变成合法动作。接触力仍然不是真机上的接触力。
遥操作与公开机器人数据DROID、AgiBot World，以及自有桌面双臂、移动平台 QUANTA X1 / X1 Pro、轮式人形 QUANTA X2。成功演示里很少出现滑脱、重抓。

2.1 两种采集方式

结构化

事先规定任务、起点和终点。一条录像就是一次命名任务。失败的复位、被截断的开头和结尾会删掉。

非结构化

操作员在真实场景里自由移动，采集时不画任务边界。录像先做时间对齐，再切成后面的四层字幕。

生产配方里，真机数据只占一小部分，用来锚定物理尺度。更大量的片段来自手持设备，因为采集速度不再受机器人台时限制。

2.2 主动补上接触附近的失败

聚类只能把数据里已经出现的恢复动作找出来。接触点附近如果从来没采过，聚类也补不出样本。论文在每个接触事件 \(e\) 的名义位形 \(q_e^\star\) 周围画一个小球，在球里扰动初始位姿，然后重放原来的演示，或者重新采一条恢复轨迹。

\[ \tilde p_{\mathrm{train}}(q, e) = (1-\alpha)\, p_{\mathrm{nominal}}(q, e) + \alpha\, \mathbb{E}_{e}\bigl[p(q\mid e)\bigr] \]

\(\alpha\) 是一个小权重。第二项只覆盖接触点附近，不把机器人扔到无关的位姿上。

3. 前处理

顺序不能颠倒：先把视频和动作拨到同一时刻，再清洗，再写字幕，最后聚类。如果字幕写在未对齐的时间轴上，「抓住」会被标到还在靠近杯子的画面上。

3.1 估计视频和动作之间的固定延迟

相机编码、控制器日志和落盘，会让同一段录像里的画面和动作相差一个近似常数的时间 \(\Delta\)。在 20 帧每秒的数据上，差 2 帧就是大约 100 毫秒。对抓取来说，这 100 毫秒足够把「靠近」变成「已经碰到」。

对齐时做五件事。

  1. 自我视角和腕部相机转成灰度并归一化，计算帧与帧之间的光流。光流大，表示画面在动。
  2. 对左右末端位置做差分。差分大，表示手在动。
  3. 两条曲线都做平滑和归一化。
  4. 在一个小的整数窗口里滑动动作曲线，找到与光流曲线相关性最大的滞后。
  5. 把多个相机、左右手的投票合在一起，避免一次遮挡或一只静止的夹爪决定整个偏移。

找到偏移之后，动作序列按视觉时间轴重新编号。平移造成的头尾空帧删掉。连续的动作数值只在对齐完成之后才重采样。

如果最佳滞后的相关很弱，或者同一数据源里不同录像投出的滞后互相矛盾，或者需要的平移超出预期窗口，这条数据不直接进入训练。它会被单独拿出来检查，或者降权，直到这个数据源的延迟被确认。

3.2 清洗

删掉这些录像：缺相机、动作时间戳倒退或重复、帧率异常、视频长度和动作长度对不上、机器人状态非法、轨迹在运动学上断开、夹爪状态损坏、重定向之后超出真机可达空间。结构化数据再删掉失败复位和截断的起止。

留下来的每条录像都带同一套标记：已对齐的多相机视频、对齐后的动作、相机参数、机器人状态、数据来源、置信度和清洗记录。后面的字幕和采样器都读这些标记。

3.3 四层字幕

切分按动作边界，不按固定帧数。仍用杯子的例子：

层这一层写什么杯子任务里的例子
Task整段录像的目标把杯子放进盒子
Subtask少数几个连续阶段接近杯子；建立抓取；搬运；放入
Action可执行的短动作伸手、对齐、合爪、抬起、平移、松开
Segment更短的局部事件第一次没夹住，腕部挪了 2 厘米再夹

还有一个可选的人工层，只标在抽查过的录像上，用来检查自动边界准不准。不是每条数据都有人工层。

Segment 这一层是为了保住失败和修正。如果整段只有一句「把杯子放进盒子」，滑脱和重抓会被写进成功句里，采样时也无法单独把它们抽出来。

3.4 截断和去掉静止帧

事件时长不同，网络的输入长度要有上限。视频预训练把每段截到最多 65 个潜帧。潜帧和原始帧的换算在第 5.2 节：按论文的 stride-2 下采样，65 个潜帧对应 129 个原始帧。

构造事件时还会剪掉几乎不动的帧。flow matching 的监督因此落在末端确实在动的区间上。

3.5 聚类后再采样

原始数据是长尾的：大量录像都是「伸手、抓起、放下」，滑脱和重试很少。如果按自然频率训练，模型会倾向高频的顺利轨迹。

论文做两趟离线聚类，训练时只使用簇编号，不再把编码器跑一遍。

  • 视觉–语言簇：冻结的多模态编码器把「画面 + 字幕」映射到同一空间，按主题分成指令和场景的组合。
  • 动作簇：只在轨迹空间里聚类。恢复、重抓、接触修正会形成自己的簇，而不是淹没在「抓」这个动词里。

先按动作边界切开，再聚类。切完之后，语言分布比「一条录像一句任务描述」更均匀。采样器同时平衡这两种簇。

4. 数学

4.1 先看 flow matching 在做什么

以动作轨迹为例。干净轨迹记为 \(a_0\)，纯噪声记为 \(\varepsilon\)。训练时不要求网络一步输出 \(a_0\)。它学习的是从噪声走回 \(a_0\) 的速度。

论文使用一条直线插值。时间 \(t\) 从 0 到 1 时，带噪轨迹是

\[ a_t = (1-t)\, a_0 + t\, \varepsilon \]

这条直线对 \(t\) 的导数是常数

\[ v^\star = \varepsilon - a_0 \]

这就是 v-prediction 的目标。网络看到 \(a_t\) 和 \(t\)，输出 \(\hat v\)。损失是 \(\hat v\) 和 \(v^\star\) 的均方误差。

视频侧完全相同，只是对象从轨迹换成 VAE 潜变量 \(z_0^V\)：

\[ C^{V\star} = \varepsilon^V - z_0^V \]
\[ \mathcal{L}_V = w_V(t^V)\, \lVert \hat C^V - C^{V\star} \rVert^2 \tag{7} \]

\(w_V(t^V)\) 是按噪声水平可选的权重。损失只在有效图像块上计算。画面以外的区域和合成黑边不进入这个均方误差。论文把这叫做 border masking，所有视频训练都打开。

如果打开了第 5.3 节的 tube 遮挡，被遮住的时空区域 \(\mathcal{T}\) 用同一个目标，但多乘一个权重 \(\lambda_{\mathrm{mask}}\)：

\[ \mathcal{L}_V = w_V(t^V)\Biggl( \sum_{u\notin\mathcal{T}}\lVert \hat C^V_u - C^{V\star}_u\rVert^2 + \lambda_{\mathrm{mask}}\sum_{u\in\mathcal{T}}\lVert \hat C^V_u - C^{V\star}_u\rVert^2 \Biggr) \tag{8} \]

主实验把 tube 关掉，也就是 \(p_{\mathrm{tube}}=0\)。此时公式 (8) 退回公式 (7)。

4.2 动作损失

动作塔默认也预测速度，目标是 \(v^{A\star}=\varepsilon^A-a_0\)。视频塔在这一阶段是冻结的。一个优化步可以抽 \(K\) 个不同的动作噪声，它们共用同一次视频前向：

\[ \mathcal{L}_A = \frac{1}{K}\sum_{k=1}^{K} w(t_k^A)\, \lVert \hat y_k^A - y_k^{A\star}\rVert^2 \tag{13} \]

主实验取 \(K=6\)，并且 \(\hat y\) 就是预测速度。\(K\) 只出现在训练里。推理时每个控制周期只走一条去噪轨迹。

接触事件往往只有几帧。速度预测在高噪声时会把这几帧的权重压得很低。论文因此留了一个可选项：网络直接预测干净动作 \(a_0\)，称为 x-prediction。还可以加上离散余弦变换的辅助项，让损失更关心整条轨迹的形状，而不是相邻帧的抖动。主实验这两个选项都关闭。

4.3 视频去噪和动作去噪为什么不对齐

动作第 \(j\) 步做交叉注意力时，必须读取某一步的视频特征。这个对应记为 \(m(j)\)。

对应关系什么时候用
对称\(m(j)=j\)小数据上视频塔和动作塔一起更新。
非对称\(m(j)=s^\star\)主配方。动作的每一步都读同一次视频前向。

主配方的日程一共 50 步，锚点固定在

\[ N_d = 50, \qquad s^\star = 45, \qquad m(j)=45 \quad \text{对所有 } j \]

原因可以分成计算和监督两半。

  • 视频塔已经冻结。动作的正确答案来自数据集里的轨迹，不来自视频网络当场生成的画面。若让视频走到很噪的步数，那些特征对不上这段真值轨迹。若让视频走到几乎干净的步数，特征里又缺少仍可用来引导控制的结构。
  • 所以视频只算到第 45 步，停在中等噪声。动作的 50 个噪声水平都看这一份特征。训练时锚点允许小幅抖动。推理时锚点固定。

4.4 长事件更容易丢掉字幕

事件越长，模型越可能只靠字幕记住后半段，而不看当前画面。丢掉字幕的概率 \(\rho\) 随原始帧数 \(L_e\) 从 0.1 升到 0.9，中间用升余弦：

\[ \rho(L_e)= \begin{cases} 0.1, & L_e \le 129, \\[4pt] 0.1 + 0.8\cdot\dfrac{1-\cos\bigl(\pi \dfrac{L_e-129}{220-129}\bigr)}{2}, & 129 < L_e < 220, \\[10pt] 0.9, & L_e \ge 220. \end{cases} \tag{20} \]

129 与第 3.4 节的截断长度相同。字幕被丢掉的那一步，网络只能根据当前多相机画面，推断接触和末端接下来会怎样动。

4.5 动作写成相对位移

事件训练时，每个潜帧 \(f\) 上的图像块共享时间索引 \(\tau=f\)。状态量和第 0 个潜帧的索引都是 0。动作 token 每 \(K_p\) 个对齐一个未来潜帧：

\[ \tau^A_0 = 0, \qquad \tau^A_{1+k} = \left\lfloor \frac{k}{K_p} \right\rfloor + 1 \tag{10} \]

统一模式还要看历史。窗口是 \(M\) 帧历史、1 个当前锚点、\(N\) 帧未来。锚点上的动作 token 写成 0，用来固定时间原点。锚点之前的 token 是从锚点往回看的位移，锚点之后的 token 是从锚点往前走的位移。机器人的绝对构型不写进这条相对轨迹，它留在单独的状态 token \(s\) 里。

4.6 视线锥：训练时哪些图像块可以互相看

三个相机并不看同一块空间。如果让所有图像块自由互看，注意力会把不相干的背景混在一起。论文在训练时用标定计算一个掩码，推理时再把掩码拿掉，所以部署不需要标定。

同一潜帧上的两个图像块 \(u\) 和 \(u'\)，各自的视锥近似成一个圆锥：顶点在相机光心，轴指向图像块中心，半顶角刚好包住这个图像块。在景深区间 \([d_{\min}, d_{\max}]\) 里，如果两个圆锥有交，则这两个图像块允许互看。

\[ \mathcal{M}_{\mathrm{sc}}[u,u'] = 1 \quad\Longleftrightarrow\quad \text{两个视锥在景深范围内相交} \tag{6} \]

注意力logit 上加的偏置是 \((1-\mathcal{M}_{\mathrm{sc}})\cdot(-\infty)\)。同一相机内部始终允许互看。这个掩码每个样本算一次，所有层共用。它只改变注意力，不改变哪些 token 进入视频损失。

4.7 文本条件的两个损失

后面会把 T5 换成一个视觉语言模型。为了不重训视频网络，视觉语言模型输出的条件 \(c_\ell^{\mathrm{VLM}}\) 要对齐到原来的 T5 特征 \(c_\ell^{\mathrm{T5}}\)。同时监督两件辅助事：下一事件的字幕，以及当前事件还剩多少时间。

\[ \mathcal{L}_{\mathrm{text}} = \lambda_{\mathrm{align}}\lVert c_\ell^{\mathrm{VLM}}-c_\ell^{\mathrm{T5}}\rVert^2 + \lambda_{\mathrm{next}}\, \mathrm{CE}(\hat c_{\mathrm{next}}, c_{\mathrm{next}}) + \lambda_{\mathrm{time}}\, \mathrm{Huber}(\widehat{\Delta t}, \Delta t) \tag{21} \]

统一模式里的连续思维向量不逐个字生成。它们先被投影成一个短前缀，再交给一个冻结的 Qwen3.5-0.8B，让这个小模型把原来的文字思维链 \(r_{1:M_r}\) 重建出来：

\[ \mathcal{L}_{\mathrm{CoT}} = -\sum_{m=1}^{M_r} \log P_{\phi}\bigl(r_m \mid z_{1:K_c},\, r_{<m}\bigr) \tag{19} \]

梯度只进入思维支路和前缀投影。0.8B 模型不更新。这样连续向量要装下高层语义，而不是模仿逐 token 的隐状态。

5. 模型

主干是两座同样深的 DiT。一座继承文生视频模型 Wan，负责未来画面。一座随机初始化，负责末端轨迹。视频生成评测使用的视频塔从 Wan2.2-5B 初始化。图像先经过冻结的 3D 因果 VAE，网络在潜变量上做去噪。

5.1 原始帧如何变成潜帧

VAE 的时间打包规则是「开头 1 帧，后面每 4 帧压成 1 个潜帧」。

\[ \underbrace{1}_{\text{当前帧}} + 4N \text{ 个原始帧} \quad\longrightarrow\quad \underbrace{1}_{\text{条件潜帧}} + N \text{ 个待去噪潜帧} \]

事件训练时，当前画面放在开头那一帧。网络只去噪后面的 \(N\) 个潜帧。

统一模式还要看历史。在当前帧前面再接 \(4M\) 个原始帧，一次编码整段 \(1+4M+4N\)。得到 \(1+M+N\) 个潜帧，历史和未来之间没有第二次编码的接缝。网络仍然只去噪最后 \(N\) 个未来潜帧，历史潜帧只作为条件。

5.2 视频塔的一个 block

Wan 原来的视角内自注意力和 3D RoPE 保持不动。每个相机先作为自己的 batch 项进入。多相机时，每个 block 在视角内注意力之后多一条跨视角支路。

  1. 按潜帧，把 \(N_v\) 个相机在这一帧上的图像块拼成一条序列。
  2. 位置编码从 \((f,h,w)\) 扩到 \((f,h,w,\mathrm{view})\)。view 这一维来自每个相机一个可学习向量，所有层共用。增加或去掉一个相机，只改这张表。运行时不输入标定外参。
  3. 这条支路的注意力权重，用该 block 原有的视角内自注意力初始化。
  4. 输出乘一个从零开始的投影 \(W_{\mathrm{view}}\)，再乘 AdaLN 的门 \(g_i\)，加回原特征：
\[ h_i^V \leftarrow h_i^V + g_i\, W_{\mathrm{view}}\, \mathrm{CrossViewAttn}_i(h_i^V), \qquad W_{\mathrm{view}}\text{ 的初值为 } 0 \tag{1} \]

零初始化的作用很具体：训练的第一步，跨视角支路的输出是 0，Wan 原来的外观和语言对齐还在。跨相机关联是后来学出来的。

训练时还可以随机遮住一个相机上的一小块空间，并且沿所有潜帧都遮住，这块区域叫做 tube。遮住之后，单靠这个相机自己的前后帧补不回来，网络只能向其他相机要信息。窗口必须落在至少能被另一个相机看到的地方。主配方不用 tube，只保留视线锥和黑边屏蔽。

5.3 动作塔的一个 block

一个共享的 MLP 把本体状态 \(s\) 和带噪动作都映射到宽度 \(d\)。随后每个 block 按固定顺序做四件事。

  1. 动作 token 之间做自注意力，时间用一维 RoPE。
  2. 再单独和状态 token 做一次交叉注意力。这样绝对构型不会被很长的视频序列稀释。
  3. 读取同一深度的视频特征。等深时，动作第 \(i\) 层读视频第 \(i\) 层。
  4. 经过带门控的前馈网络。

交给动作塔之前，各相机的视频 token 沿序列维拼起来，并加上窗内时间嵌入 \(E_\tau\)。统一模式再加一个窗口编号嵌入 \(E_{\mathrm{abs}}\)，用来区分「这是第几个定长窗口」。

\[ \tilde h_i^V = \mathrm{ViewConcat}\bigl(h_{\pi(i)}^V\bigr) + E_\tau(\tau^V) + E_{\mathrm{abs}}(t_{\mathrm{abs}}) \tag{9} \]

等深网络里 \(\pi(i)=i\)。\(\tilde h_i^V\) 是动作交叉注意力的 key 和 value。事件训练时 \(E_{\mathrm{abs}}\) 关闭。

耦合是单向的。动作层读取视频层。视频 DiT 上没有从动作回来的支路。动作损失的梯度停在动作塔里。

最后的 MLP 把头把动作 token 映回末端动作的维度 \(D_a\)。

5.4 语言支路

事件模式可以直接使用一句下一事件的文字。这句文字在早期训练里由冻结的 T5 编码。后来换成冻结的 Qwen3.5-9B，但它输出的向量要对齐到 T5 的特征空间，视频塔因此不用重训。

统一模式如果每次都逐字生成思维链，延迟会随思维长度线性增加，而且底层的视觉语言特征会被重复计算。Staircase 把网络在深度 \(N_r\) 处切开：

  • 只有第一个思维位置走过 \(N_r\) 以下的层，得到一份共享的视觉语言特征。
  • 其余 \(K_c-1\) 个连续向量在 \(N_r\) 以上并行生成。
  • 这些向量直接进入世界模型的交叉注意力，中间不采样离散 token。

6.1 视频预训练

只更新视频 DiT，动作塔还没接上。条件是当前多相机画面，以及 T5 编码后的事件字幕。噪声时间步均匀采样。跨视角投影从 0 开始。字幕按第 4.4 节的概率丢掉。权重做指数滑动平均，衰减系数 0.9999。不同长度的事件按潜变量形状分桶，减少填充。采样用第 3.5 节的双簇均衡。

6.2 动作预训练

载入上一段的视频 DiT 并冻结，关掉视频损失。动作塔随机初始化。视频前向停在第 45 步。一个优化步抽 6 个动作噪声，共用这一次视频特征。数据布局仍是变长事件，不是定长窗口。

6.3 把条件从 T5 换成视觉语言模型

Qwen3.5-9B 的主体冻结。一次前向要产出三样东西：对齐到 T5 空间的条件向量、下一事件字幕、当前事件的剩余时间。损失是公式 (21)。下游 DiT 在这一段不更新。

6.4 Staircase

只更新思维支路和前缀投影。监督是公式 (19)：冻结的 0.8B 模型能否从这些连续向量里把文字思维链读出来。

6.5 可选的定长适配

如果部署时每次只执行固定的 \(H_a\) 步，需要这一段。两座 DiT 一起在「历史 + 当前 + 未来」窗口上更新。全局指令来自 Task 层，仍由冻结的 T5 编码。锚点仍是 45。因为窗口切法变了，视觉–语言聚类和动作聚类要在新窗口上重做一遍。

只跑事件模式的话，这一段可以不做。

6.6 和算法绑在一起的三个实现选择

  • 多个事件拼进同一条序列，用注意力掩码禁止跨事件看见。这样每个优化步的有效批量不随录像长短变化。
  • 优化器主体用 Muon。分片训练时 Newton–Schulz 很贵，论文的 DMuon 给每个矩阵指定一个负责的 rank，把参数同步从 all-reduce 改成 reduce 加 broadcast，并与下一步前向重叠。
  • 每层有视角内注意力和跨视角注意力。序列并行下如果朴素实现，每层要做四次 all-to-all。调度把通信叠进注意力计算里。

8. 输出之后

8.1 从网络输出到机器人指令

网络给出的是相对当前观测位姿的末端位移。锚点是 0。把未来 token 从锚点开始累加，得到这一段事件或这一个窗口的末端轨迹。当前的绝对构型来自状态 token，不从相对位移里反推。

手持数据在进入训练集之前，已经用部署机器人的 URDF 做过逆运动学。模型看到的动作维度与真机末端一致。

事件模式把这一段的自然时长执行完，再取新的观测。统一模式每次只执行固定的 \(H_a\) 步，然后窗口向前滑动。

8.2 把 50 步压缩到可以闭环

50 步去噪、每步一次大网络前向，来不及放进机器人的控制周期。论文用两步压缩。

第一步是分布匹配蒸馏。学生只用很少的采样步。它不对齐教师的每一步轨迹，而对齐最终样本的分布。损失里有两项分数：冻结教师的分数，以及一个在线跟着学生分布走的分数网络。学生被推向「教师有概率、学生还很少生成」的区域。

只做分布对齐，动作头会漂。论文把原来的动作预测损失留在蒸馏目标里。去掉这一项后，动作平均绝对误差变差 53%。学生用教师的权重初始化。部署时只保留学生。

第二步是 FP8 量化。权重量化后离线打包。激活的缩放和类型转换写进前一个算子的收尾，避免把整块激活再读写一遍。再用 CUDA Graph 去掉每步去噪的主机启动开销。论文给出的结果是，这套栈把端到端推理收到 10 Hz。

9. 推理

两种模式都使用第 4.3 节的锚点：视频网络只前向到第 45 步，动作网络走完自己的去噪步，每一步的视觉特征都来自这一次视频前向。上机时走的是蒸馏后的少步学生，不是 50 步教师。

9.1 事件模式

观测\(V_0, s\)
→
下一事件人给出，或由 Qwen 头给出
同时给出剩余时间
→
去噪变长的视频潜变量和末端轨迹
→
执行按这段的自然时长走完
→
新观测再要下一条事件

这个模式不需要历史窗口，也不需要第 6.5 节的定长适配。

9.2 统一模式

每次预测固定的 \(H_a\) 步。条件是当前画面、一段历史，以及文本槽里的 \(c_\ell\)。\(c_\ell\) 可以是第 7 节的三种来源之一。因为它们只替换交叉注意力的文本输入，一次滚出中途可以从全局指令换成 Staircase，去噪器权重不用重载。

定长窗口如果只有整句任务、没有历史，局部动作是欠定的：「把杯子放进盒子」不能唯一决定接下来 1 秒该伸手还是该松开。历史帧把「刚刚已经抓住」写进条件，问题才重新变得可解。这是统一模式要看 \(M\) 帧历史的原因。
