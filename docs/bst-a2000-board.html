1. 串口：一根线，四个设备

控制板插上电脑之后，/dev 里新出现四个串口：ttyACM0、ttyACM1、ttyACM2、ttyACM3。四个名字来自同一条 USB 设备，不是四根 USB 线。lsusb 里只有一条新设备：

1a86:55d5  QinHeng Electronics USB Quad_Serial
厂商字符串  wch.cn
序列号      wch.cn_USB_Quad_Serial_0123456789

沁恒四串口芯片把四路 UART 做在同一个 USB 器件里。Linux 的 CDC ACM 驱动给每一路建一个 ttyACM。四路的 USB 路径都是 usb1/1-10，接口号是 1.0、1.2、1.4、1.6。中间空掉的奇数号是每路串口配套的控制接口，不会再出现成一个串口设备。

先用 115200 打开 ttyACM0 时，屏幕上是一串 �。口是对的，波特率不对。控制台参数是 38400，8 数据位，无校验，1 停止位。改成 38400 之后按回车，出现 login:。

picocom -b 38400 /dev/ttyACM0

登录用户 root，密码 bst2025。进去之后的提示符是 root@vision:~#。退出 picocom 是 Ctrl-A 然后 Ctrl-X。

电脑这边要有串口权限。 /dev/ttyACM* 属于 dialout 组。不在这个组时，用 sudo picocom，或者 sudo usermod -aG dialout $USER 之后重新登录。

2. 登录之后看到的系统

主机名 vision。系统是 Ubuntu 24.04.4 LTS，内核 6.6.64-rt47，带 PREEMPT_RT，架构 aarch64。设备树里的型号字符串是：

BST A2000 BSP EVB 1.0 96G
compatible: bst,a2000

Python 是 3.12.3。板上已经装了黑芝麻的 BSP 包 bst-hanhai-bsp-binary 1.1.0.4，以及编解码、ISP、硬件视觉和网络相关的 bst-hanhai-* 组件。NPU 运行库是 libbsnnrt.so.0.12.0，头文件在 /usr/include/bsnn/bsnn.h。

3. 算力、内存、硬盘

CPU 是 ARM Cortex-A78AE。lscpu 看到 16 个核都在线，编号 0 到 15。内核把 12 到 15 核隔离了，nproc 因此是 12：普通进程调度在前 12 个核上。cpufreq 里没有频率，这里不写主频。

项目实测
CPUCortex-A78AE，16 核在线，12–15 被隔离，用户态可见 12 核
缓存L1 数据 1 MiB，L1 指令 1 MiB，L2 8 MiB，L3 8 MiB
内存共 92 GiB，当时已用 1.3 GiB，可用约 91 GiB，没有 swap
硬盘sda 119.2 GB，型号 KLUDG2RHVF-B0EQ
根分区sda3 118.8 GB，ext4，挂在 /。文件系统显示 117 GB，已用 5.9 GB，剩余 105 GB
其他分区sda1 256 MB、sda2 128 MB，都是 ext4，未挂到根上

人工智能加速器是一颗 NPU，驱动名 bstnpu，设备节点 /dev/bstnpu。内核启动日志显示探测成功：用户态运行时 v0.12.0，内核模块 bstnpu-v0.4.11。同机还有 DSP（/dev/bstdsp）和硬件视觉模块（/dev/bst_hwcv）。Mali GPU 同样探测成功，DDK r47p0，架构 9.14.5，设备名 mali0。Mali 负责图形显示。这次网络推理不经过 Mali。

lspci 里只有两座厂商号 1ef1 的桥，没有独立显卡。NPU 的算力数字没有写在 dmesg 或 sysfs 里，这次报告不引用宣传册上的 TOPS。

4. 四个网口怎么配

刚登录时，ifconfig 里有六块接口。真正的有线口是 eth0 到 eth3。当时四口都是管理状态 UP，但没有 RUNNING，收发包都是 0，也没有 IPv4 地址。网线还没建立链路。docker0 的 172.17.0.1/16 是 Docker 网桥，lo 的 127.0.0.1 是本机回环，这两块不用改。

原配置在 /etc/netplan/00-installer-config.yaml，渲染器是 NetworkManager，只给 eth0 开了 DHCP。同目录的 90-virtual_ap.yaml.example 是示例，netplan 不读取这个文件。

四个口要同时写上地址时，每个口用自己的网段。同一段地址拆到多口上，回包会从另一口出去。外网那一口用 DHCP：地址、网关和 DNS 由交换机那一侧的服务器下发，所以必须插上网线才有地址。另外三口是固定地址，不依赖网线也能先挂到接口上。

网口地址作用
eth0192.168.1.110/24固定。开发设备用 192.168.1.0/24
eth1192.168.2.110/24固定。开发设备用 192.168.2.0/24
eth2192.168.3.110/24固定。开发设备用 192.168.3.0/24
eth3DHCP插到办公室交换机后获取地址，用于外网下载。开发电脑在 10.106.253.101/22，网关 10.106.252.1。接到同一台交换机时，地址落在这个网段

这份 yaml 已经写入 /etc/netplan/00-installer-config.yaml，netplan apply 也执行过。当时四口都没有网线，NetworkManager 在没有载波时不挂地址，所以 ip addr 里仍然只有 lo 和 docker0。配置文件本身是成功的，重启也不需要。地址要等网线插上，或者按附录在无载波时挂上固定地址。

外网不是“有一个 IP 就通”。 eth3 要出现 10.106.x.x，然后 ping 10.106.252.1 和 ping mirrors.aliyun.com 都有回复，才说明能下载。固定地址那三口只和各自网段里的设备通信。

5. NPU 上怎么做推理

NPU 运行已经编译好的 BSNN 模型，不直接加载通用框架的权重。运行时读入 metadata.bin，把输入张量交给 NPU，再取回输出张量。

示例都在 /userdata/bsnn/：

路径内容
/userdata/bsnn/models/Resnet50Quant/量化 ResNet50。入口是 metadata.bin，同目录还有权重、命令和样例输入
/userdata/bsnn/app/bsnn_sample_bench_N5加载模型并计时的示例程序
/userdata/bsnn/bsnn-slt.sh自检脚本，内部调用 bsnn_sample_internal -m .../metadata.bin
/userdata/hwcv/图像缩放、色彩转换、畸变校正。这里只做图像处理，不执行网络

模型报告里的生成器是 bstnnx-patriot-v0.0.17。根文件系统里有运行库和已经转好的 ResNet50，没有主机端的转换器。新模型在带转换工具的电脑上量化，生成和 Resnet50Quant 同样结构的目录，再把整个目录拷到 /userdata/bsnn/models/。

bsnn.h 里的张量类型包括 int8、int16、fp16、uint8，图像布局包括 RGB888 和 NV12。查询接口给出输入输出个数、形状和芯片类型，然后提交一帧。

6. ResNet50 这次跑出了什么

在已经登录的串口里执行：

/userdata/bsnn/app/bsnn_sample_bench_N5 \
  -m /userdata/bsnn/models/Resnet50Quant/metadata.bin \
  -l 10

终端输出 success!。模型名 Resnet50Quant，目标 N5，UID 55c88632。报告写明 with_rvv_nodes: false、with_dsp_nodes: false，这 10 帧只在 NPU 上算。输入张量 data 是 0x24c00 字节，也就是 150528 字节，等于 224×224×3。输出张量 resnetv17_dense0_fwd 是 0x3e8 字节，等于 1000，对应 1000 个类别。权重约占 0.03 GB，内存从 CMA / dma_heap 分配。

10 帧的合计时间是 5.20 ms，输出中的吞吐是 1921.60 FPS。两者对得上：单帧大约 0.52 ms。frame_id 从 0 排到 9，然后 Producer exit(0)。

这次证明的是执行，不是识别正确率。 输入用的是模型目录里准备好的 input_0.bin，不是摄像头。命令没有加 -c，所以没有和标准输出对比。加 --save-output 可以把输出张量留下。

附录 · 逐步操作

以下命令按这次已经走通的顺序排列。串口命令在开发电脑上执行，出现 root@vision 之后的命令在登录后的 shell 里执行。

  1. 确认串口设备

    插上控制板，在电脑上看是不是沁恒四串口。四个 ttyACM 的序列号应当相同。

    lsusb | grep 1a86:55d5
ls -l /dev/ttyACM*

  2. 打开控制台

    电脑上需要 picocom。若 apt 被别的坏包挡住，先处理那个包再安装。控制台波特率用 38400。

    sudo apt install picocom
picocom -b 38400 /dev/ttyACM0

    按回车。出现乱码就退出，确认没有打成 115200。另外三路没有登录提示，不要往那三路上输入命令。退出是 Ctrl-A、Ctrl-X。

  3. 登录

    login: root
Password: bst2025

    提示符变为 root@vision:~#。

  4. 核对硬件

    uname -a
cat /etc/os-release
tr '\0' ' ' < /proc/device-tree/model; echo
lscpu
nproc
cat /sys/devices/system/cpu/isolated
free -h
df -hT
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,MODEL
dmesg | grep -Ei 'npu|mali|A2000' | head -40

    对照第 3 节的表。隔离核应是 12-15，内存大约 92 GiB，根分区剩余大约 105 GB，dmesg 里应有 bstnpu probe success。

  5. 写入四个网口

    覆盖 netplan 文件。固定地址分属三个网段，eth3 动态获取。文件权限收成只有 root 可读，避免 netplan apply 报 “permissions are too open”。

    cat > /etc/netplan/00-installer-config.yaml << 'EOF'
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    eth0:
      dhcp4: no
      addresses:
        - 192.168.1.110/24
    eth1:
      dhcp4: no
      addresses:
        - 192.168.2.110/24
    eth2:
      dhcp4: no
      addresses:
        - 192.168.3.110/24
    eth3:
      dhcp4: yes
EOF
chmod 600 /etc/netplan/00-installer-config.yaml
netplan apply

    不需要重启。没插网线时，ip -4 addr 可能仍只显示 lo 和 docker0。这是 NetworkManager 在没有载波时不挂地址，不是文件没写上。用 cat /etc/netplan/00-installer-config.yaml 确认内容还在。

  6. 没插线时也挂上三个固定地址

    eth3 的 DHCP 必须等网线插上、对端有 DHCP 服务器才有地址。下面这条只影响三个固定口。

    mkdir -p /etc/NetworkManager/conf.d
cat > /etc/NetworkManager/conf.d/ignore-carrier.conf << 'EOF'
[device]
match-device=interface-name:eth0;interface-name:eth1;interface-name:eth2
ignore-carrier=true
EOF
systemctl restart NetworkManager
netplan apply
ip -4 addr

    此时应能看到 192.168.1.110/24、192.168.2.110/24、192.168.3.110/24。没有网线时，别的机器仍然 ping 不到这些地址。

  7. 插线并检查链路

    cat /sys/class/net/eth0/carrier \
    /sys/class/net/eth1/carrier \
    /sys/class/net/eth2/carrier \
    /sys/class/net/eth3/carrier

    输出按 eth0 eth1 eth2 eth3 的顺序，1 表示这口已经插上。192.168.1.x 的设备插 eth0，办公室网线插 eth3。然后：

    netplan apply
ip -4 addr show eth3
ping -c 3 10.106.252.1
ping -c 3 mirrors.aliyun.com

    第一条 ping 通说明到了办公室网关，第二条通说明域名和外网都可用，这时才能 apt 或 wget。

  8. 跑通 NPU 上的 ResNet50

    /userdata/bsnn/app/bsnn_sample_bench_N5 \
  -m /userdata/bsnn/models/Resnet50Quant/metadata.bin \
  -l 10

    正常结束时有 success!，Total processed: 10，合计时间约 5.20 ms，FPS 约 1921。要保存输出张量，加上 --save-output。要和目录里的参考输出对比，加上 -c。

  9. 换自己的模型

    在带 bstnnx 的电脑上把网络量化编译成一套目录，里面要有 metadata.bin。把目录拷到 /userdata/bsnn/models/新模型/，然后把上面的 -m 指到新的 metadata.bin。图像缩放和色彩转换用 /userdata/hwcv 里的工具，不放进 NPU 这一步。
