1. 系统总图

SFT 不接触真机控制环。它只消费已经落盘的示教。训练机读 LeRobot，写出 JAX checkpoint；推理机以后再把这个 checkpoint 接到 Cobot Magic。两条链路只通过权重和 norm_stats 耦合。

3. 可落地步骤

  1. 确认示教已经是单右臂 7 维

    Cobot Magic 双臂原始 qpos 是 14 维（左 7 + 右 7）。单臂策略只吃右臂。采集侧与 real_env.get_observation 一致：qpos[7:14]，图像只留高位相机和右腕相机。

    每一帧动作与下一帧关节同空间：前 6 维是弧度关节目标，第 7 维是归一化夹爪（0 关，1 开）。不要在 HDF5 里预先做 delta；delta 由训练变换统一减去当前 state。

  2. 转成 LeRobot，repo 名用本例全名

    脚本是 examples/mobile_aloha_AgileX/convert_aloha_data_to_lerobot.py。它把 HDF5 写成 observation.state、action、observation.images.cam_*。若原始文件仍是 14 维双臂，先切出右臂 7 维再写入，键名保持 cam_high 与 cam_right_wrist。

    export HF_LEROBOT_HOME=/workspace/huggingface/lerobot
export HF_ENDPOINT=https://hf-mirror.com
uv run examples/mobile_aloha_AgileX/convert_aloha_data_to_lerobot.py \
  --raw_dir /data/raw/screw_sorting_single_sft_ep280_v30_steam \
  --repo_id screw_sorting_single_sft_ep280_v30_steam

    转换后抽查一条：observation.state.shape == (7,)，action.shape == (7,)，图像为 uint8 HWC，episode 数等于 280。

  3. 把配置的 repo_id 指到这个数据集

    编辑 pi05_cobot_screw_sorting_single 里的 LeRobotCobotSingleArmDataConfig：

    data=LeRobotCobotSingleArmDataConfig(
    repo_id="screw_sorting_single_sft_ep280_v30_steam",
    assets=AssetsConfig(
        assets_dir="/workspace/openpi/assets/pi05_cobot_screw_sorting_single",
        asset_id="screw_sorting_single_sft_ep280_v30_steam",
    ),
    default_prompt="Please sort and return the silver screws in the grey box to their proper places",
    repack_transforms=...  # cam_high, cam_right_wrist 两路，保持现有映射
)

    asset_id 必须和以后 norm_stats.json 所在子目录同名。推理加载 checkpoint 里的 assets 时用的就是这个 id。

  4. 先算归一化，再开训练

    scripts/compute_norm_stats.py 走和训练相同的 repack、delta、pad，只是还没做分位数缩放。π0.5 的 use_quantile_norm 为真（model_type != PI0），所以落盘的是 q01 / q99，不是均值方差。

    export CUDA_VISIBLE_DEVICES=0,1,2,3
export XLA_PYTHON_CLIENT_MEM_FRACTION=0.9
uv run scripts/compute_norm_stats.py --config-name pi05_cobot_screw_sorting_single
uv run scripts/train.py pi05_cobot_screw_sorting_single \
  --exp-name=pi05_cobot_screw_sorting_single

    对应 finetune_screw_sorting.sh 的四步开关。那个脚本默认的 config_name 是双臂 pi05_cobot_screw_sorting，单臂例子必须改成上面的名字。

  5. 确认 checkpoint 能被推理读到

    目录形如 checkpoints/pi05_cobot_screw_sorting_single/pi05_cobot_screw_sorting_single/<step>/，里面有 params 和 assets/<asset_id>/norm_stats.json。服务端脚本 run_server_screw_sorting_single.sh 用的是 step 29999。EMA 默认 0.99，推理应加载 ema 参数（checkpoint 保存逻辑写入的那份）。

4. 一条样本怎么变成模型输入

关节差分写在 DeltaActions：

$$ a'_{t,i} = \begin{cases} a_{t,i} - s_i & i \le 5 \\ a_{t,i} & i = 6 \end{cases} $$

π0.5 分位数归一化（Normalize._normalize_quantile）把每个维度映到大约 \([-1,1]\)：

$$ \hat x = \frac{x - q_{01}}{q_{99}-q_{01}+10^{-6}}\cdot 2 - 1 $$

离散状态（PaligemmaTokenizer.tokenize）在归一化之后做：

$$ b_i = \mathrm{digitize}(\hat s_i;\; \mathrm{linspace}(-1,1,257)[:-1]) - 1 \in \{0,\ldots,255\} $$

于是本体感觉不再作为连续 token 进入动作专家。这是 π0.5 相对 π0 的结构差别：π0 用 state_proj 把 state 投成 suffix 里的一个连续 token；π0.5 把 state 写进文本，时间步则用 adaRMS 注入动作专家。

5. 模型前向与流匹配损失

Pi0.compute_loss 里的插值与目标速度是：

$$ t \sim 0.999\cdot \mathrm{Beta}(1.5, 1) + 0.001 $$
$$ x_t = t\,\varepsilon + (1-t)\,a, \qquad u_t = \varepsilon - a, \qquad \varepsilon \sim \mathcal N(0,I) $$
$$ \mathcal L = \frac{1}{D}\sum_{d=1}^{D}\big(v_\theta(x_t, o, t)_d - u_{t,d}\big)^2 $$

对 batch 再取均值。\(t=0\) 时 \(x_t=a\)（数据），\(t=1\) 时 \(x_t=\varepsilon\)（噪声）。\(u_t\) 是这条直线从数据指向噪声的速度。推理从 \(t=1\) 积到 \(t=0\)，用的是同一支速度场，时间方向相反。图像增强发生在 preprocess_observation(..., train=True)，推理时关闭。

6. 训练步、学习率与检查点

scripts/train.py 的一步：合并参数 → compute_loss → 只对 trainable_filter 求梯度 → AdamW → 可选 EMA。默认日程在 optimizer.py：

$$ \eta_0 = \frac{2.5\times 10^{-5}}{1001},\quad \eta_{\text{peak}} = 2.5\times 10^{-5},\quad \eta_{\text{end}} = 2.5\times 10^{-6} $$

warmup 1 000，cosine 衰减 30 000 步，与 num_train_steps 对齐。AdamW 的 \(\beta_1=0.9,\ \beta_2=0.95\)，权重衰减 \(10^{-10}\)，全局梯度裁剪到 1。EMA：

$$ \bar\theta \leftarrow 0.99\,\bar\theta + 0.01\,\theta $$

日志每 100 步写 loss、grad_norm、param_norm。本配置 save_interval=5000、keep_period=5000，四卡时 batch 64 必须能被设备数整除。

权重加载是部分覆盖：CheckpointWeightLoader 只填 pi05_base 里形状对得上的叶子，动作头若与基座一致则一并带上，然后在螺丝数据上全参数微调（本配置 freeze_filter 为空）。

和推理对齐的三件事。 ① 训练用的 norm_stats 必须跟 checkpoint 的 assets 一起走，服务端从 checkpoint 读，不从训练机的 assets 目录重算。② adapt_to_pi=False，不要套 Aloha 夹爪角-线变换。③ 夹爪是绝对量，关节是相对当前 state 的 delta；推理输出侧用 AbsoluteActions 加回 state。

7. 逐张量核对

下面用一条右臂样本把形状走完。普通 SFT 配置 pi05_cobot_screw_sorting_single 不改 Pi0Config 的默认值，所以 \(H=50\)、\(D=32\)、rtc_max_delay=0。仓库里另有 pi05_cobot_screw_sorting_single_rtc，数据集名是 screw_sorting_single_sft_ep279_annotated，\(H=32\)、rtc_max_delay=10。那是另一条损失，放在 RTC 文档第 7 节。本页的数字全部按 \(H=50\) 的普通 SFT。

7.1 从 7 维关节到 32 维噪声

设当前右臂观测（弧度，夹爪已归一化）

$$ s = (0.00,\ 0.40,\ 0.80,\ 0.10,\ -0.20,\ 0.05,\ 0.90) $$

示教在 30 Hz 下第 \(k\) 拍的绝对目标 \(q_k\)。delta 掩码是 6 个真、1 个假，所以

$$ \delta_k[0\!:\!6] = q_k[0\!:\!6] - s[0\!:\!6],\qquad \delta_k[6] = q_k[6]. $$

若 0.2 秒后肩关节多转了 0.05 rad、夹爪仍张开，则 \(k=6\)（因为 \(6/30=0.2\)）那一行是 \((*, 0.05, *, *, *, *, 0.90)\)。chunk 共 50 行，时间覆盖 \(49/30\approx 1.63\) 秒。随后右侧补 25 个 0，得到 (50, 32)。补出来的维在分位数统计里没有 q01/q99，反归一化时原样返回，机器人永远只读前 7 维。

分位数作用在补零之后的每一维上。主体被映到大约 \([-1,1]\)。离散 state 再用 257 个切点里的前 256 个：

$$ \text{bins} = \mathrm{linspace}(-1,1,257)[:-1],\quad b_i = \mathrm{digitize}(\hat s_i,\ \text{bins}) - 1. $$

步长是 \(2/256=1/128\approx 0.0078\)。一个归一化关节差 0.01，档位可能差 1。这个整数串进句子 Task: …, State: …;\nAction: ，最大长度 200。图像 token 不占这 200，它们走 SigLIP。

7.2 注意力块，而不是逐拍因果

make_attn_mask 用 mask_ar 的累积和分块。图像和语言的 ar_mask 全是 False，累积和停在 0，三路相机和文本彼此全可见。左腕是黑图且 image_mask=False，对应 token 在 input_mask 里为假，既不能被看见也不能看见别人。

动作段的 ar_mask 是 [True] + [False]×49。第一个 True 让累积和从 0 跳到 1，后面 49 个 False 不再增加。于是 50 个动作 token 落在同一块里：它们互相可见，也看得见全部 prefix；prefix 的累积和是 0，看不见任何动作。这不是「第 \(k\) 拍只能看 \(0..k\)」。整段动作是一次并行回归。损失

$$ \ell_{b,k} = \frac{1}{32}\sum_{d=0}^{31}(v_\theta - u_t)_{b,k,d}^2 $$

再对 batch 和 50 个时间步取均值。pad 维上的速度误差同样进平均。若网络把 pad 预测成非零，损失会惩罚它，所以 pad 会被学成接近 0 速度，而不是被忽略。

7.3 一个流匹配步的数字

取 \(t=0.4\)，某一维上数据 \(a=0.2\)、噪声 \(\varepsilon=1.0\)。代码的插值是

$$ x_t = 0.4\times 1.0 + 0.6\times 0.2 = 0.52,\qquad u_t = 1.0 - 0.2 = 0.8. $$

网络要在这一维输出 0.8。推理从 \(t=1\) 往 \(t=0\) 走，\(\Delta t=-0.1\)（10 步）。若这一步 \(v=0.8\) 且 \(x=0.52\)，更新

$$ x \leftarrow 0.52 + (-0.1)\times 0.8 = 0.44 $$

方向是离开噪声、靠近 \(a=0.2\)。把训练改成 \(x_t=(1-t)\varepsilon + t a\) 而不改这个负步长，积分会朝噪声走。β(1.5, 1) 的密度正比于 \(t^{0.5}\)，大 \(t\) 抽得更多：网络更多练习「从接近噪声的位置报出指向数据的速度」。

7.4 学习率和 EMA 在 3 万步上的位置

默认 cosine：第 0 步学习率 \(2.5\times 10^{-5}/1001\approx 2.5\times 10^{-8}\)，第 1000 步到峰值 \(2.5\times 10^{-5}\)，第 30000 步到 \(2.5\times 10^{-6}\)。本配置 num_train_steps 正好等于 decay_steps。梯度先被全局范数裁到 1，再进 AdamW。EMA 每步

$$ \bar\theta \leftarrow 0.99\bar\theta + 0.01\theta. $$

0.99 的半衰期大约是 \(\ln 2 / 0.01 \approx 69\) 步，所以推理用的 EMA 几乎是最近一两百步的平均，不是全程平均。存盘间隔 5000 步，中间的 EMA 状态不会单独留档。

和 RTC-SFT 不要混用同一句「流匹配损失」。 rtc_max_delay=0 时，50 个时间步共享一个 \(t\)，损失盖住整段。RTC 配置把每个样本的前 \(d\) 步钉在干净示教上，损失只平均后半段，并且 \(H\) 是 32 不是 50。把普通 SFT 的 checkpoint 拿去按前缀采样，或把 RTC checkpoint 拿去整段从噪声积分，条件分布都对不上。细节在 RTC 文档。

附录 · 工程里的数学

A. 为什么用条件流匹配而不是扩散噪声预测

记数据分布的样本为动作块 \(a\in\mathbb R^{H\times D}\)，\(H=50\)，\(D=32\)（真实关节只有前 7 维，其余是 pad）。在 \(t\in(0,1)\) 上定义概率路径的条件期望直线

$$ x_t = (1-t)\,a + t\,\varepsilon . $$

对 \(t\) 求导得到常数速度 \(u_t = \mathrm dx_t/\mathrm dt = \varepsilon - a\)。条件流匹配的回归目标就是这个速度。网络 \(v_\theta(x_t, o, t)\) 在边缘化 \((a,\varepsilon,t)\) 之后，其最小二乘解逼近边缘速度场。沿该场从噪声积回数据，得到动作分布的样本。相对 DDPM 的噪声预测，这里每步是常微分方程的显式欧拉步，步数可以压到 10（推理默认 num_steps=10）。

代码里 Beta(1.5, 1) 把质量偏向较大的 \(t\)（更接近噪声）。端点被夹到 \([0.001,1)\)，避免 \(t=0\) 时速度目标与数值条件同时退化。

B. 欧拉积分与训练约定相反的时间

推理 sample_actions 明确使用扩散文献约定：\(t=1\) 是噪声，\(t=0\) 是数据，并注释这与论文示意图相反。离散化为

$$ \Delta t = -1/N,\qquad x \leftarrow x + \Delta t\, v_\theta(x, o, t),\qquad t \leftarrow t+\Delta t $$

从 \(t=1\) 出发。因为训练时 \(v_\theta\) 拟合的是「从数据指向噪声」的 \(u_t\)，乘上负的 \(\Delta t\) 就是沿速度场走回数据。若有人把训练插值改成 \(x_t=(1-t)\varepsilon+t a\) 而不改推理循环，采样会朝噪声走。

C. 注意力掩码在表达什么

embed_prefix 把图像和语言的 ar_mask 都设成 False，表示这些 token 互相全可见。embed_suffix 的动作段是 [True] + [False]*(H-1)：第一个 True 在累积异或掩码里关上「prefix 看 suffix」的门，后面的 False 让动作 token 彼此可见，并且都能回看 prefix。这就是「观察条件生成整段动作」而不是自回归逐 token 生成。损失对 50 个时间步、32 个动作维同时回归。

D. Delta 动作是把绝对轨迹变成局部增量

示教存的是绝对关节目标 \(q_{t+k}\)。若直接回归绝对角，策略必须记住整条轨迹的偏置，换一个起始姿态就偏。减去当前观测 \(s_t\) 之后，网络学习

$$ \delta_{t+k} = q_{t+k} - s_t \quad (k=0,\ldots,H-1) $$

注意减的是 chunk 起点的 state，不是相邻帧差分。推理时 AbsoluteActions 用当时的机器人 state 加回去：\(\hat q = \hat\delta + s_{\text{now}}\)。夹爪不参与这条式子，因为开合是有物理端点的绝对量，减当前开度会把「保持张开」变成 0，语义反了。

E. 分位数归一化相对 z-score

关节和夹爪的示教分布厚尾、不对称。z-score 被少数快速挥臂拉大标准差，主体动作被压进很小区间。π0.5 用经验 1% 与 99% 分位把主体映到 \([-1,1]\)，超出部分允许略微出界。反归一化是仿射逆变换，pad 维（7 之后）没有统计量，反归一化时保持原值。因此 pad 必须在归一化之前补上，并且训练、统计、推理三处 pad 宽度同为 32。

F. adaRMS 如何注入时间

π0.5 不把时间拼进动作 token。正弦位置编码

$$ \big[\sin(t\cdot\omega_k), \cos(t\cdot\omega_k)\big],\quad \omega_k \in [4\cdot 10^{-3},\, 4] $$

经过两层 SiLU MLP，得到与动作专家宽度相同的向量，作为 adaRMS 的条件。这样每个 Transformer block 的归一化缩放随 \(t\) 变化，速度场对噪声水平的依赖不必挤进 token 通道。π0 则是把时间向量和动作向量拼接后再过 MLP，没有 adaRMS。

G. 这条 SFT 目标在整个工程里的位置

SFT 估计的是示教条件分布 \(\pi_{\text{SFT}}(a\mid o)\) 的一个流匹配采样器。它不优化回报。RTC 在采样 ODE 上加前缀约束，让相邻 chunk 在已经下发的前缀上连续。RLT 先把同一条 prefix 表征压成 \(z_{\text{rl}}\)，再用在线 actor-critic 在 \(z_{\text{rl}}\) 上做局部修正。三份文档因此共享同一份螺丝分拣数据和同一台 Cobot Magic，但优化对象不同：SFT 拟合示教速度场，RTC 改采样，RLT 在冻结或联合的 VLA 之上学习紧凑表征和在线策略。
